# Densight Slides

A free platform for building and presenting interactive slide decks, with live
audience polls and quizzes. Vanilla JS, no framework. A deck is plain JSON; one
renderer draws it for the editor, the presenter and the exports.

## Design

One design system, `src/styles/tokens.css`, taken from densightlabs.com (`#2020E8` blue,
`#0F1117` ink, white and `#F8F9FB` surfaces, Inter, 16-24px radii). The home page,
dashboard, editor and phone pages all read it, in a light and a dark palette. It
follows the device by default; the sun/moon button on the dashboard and File >
Appearance in the editor switch it (remembered per browser). Tests check the
contrast of every palette pair and that every CSS variable used is defined.

## Type and look

Headlines use Newsreader (a serif), text and the interface use Inter; both are
self-hosted from `site/fonts/` (declared in `site/fonts.css`). The public pages are
deliberately plain: hairline rules and plain text instead of pill badges, chips or
card grids; flat surfaces; no floating or pulsing motion. A test fails if pill-shaped
boxes or decorative animations come back. The home page has an interactive tutorial
(`site/tutorial.js`, logic unit-tested) and SVG drawings of the block types.

## Brand and contact

The logo is the Densight Labs mark. `site/brand/` holds every size generated from the
original PNG: a dark mark for light surfaces, a light mark for dark ones, the
favicons (`favicon.ico`, 16/32/48), the Apple touch icon, the 192/512 and maskable
app icons, and the 1200x630 sharing image. The logo pair switches with the theme.
Support is `hello@densight.com` and the company link is `https://densightlabs.com`;
both are defined once in `src/shell/contact.js` (app) and the top of `tools/site.mjs`
(public pages).

## Commands

```bash
npm install
npm run dev     # http://localhost:5177 (watch + serve)
npm run build   # dist/: public pages, the app, and sw.js for offline use
node tools/serve.mjs 5178   # serve dist/ the way Netlify does (rewrites included)
npm test        # unit tests (node:test)
npm run qa      # pre-deploy check: tests, a production build, inspections (see docs/QA.md)
npm run relay   # local stand-in for a realtime server, port 5199 (see Live sessions)
```

`/` opens the editor (File > Open interactive demo loads a deck that uses every
block). `/?play` plays the sample deck in the bare player, `/?play&deck=interactive`
the interactive one, with
`&theme=densight-light|paper|midnight`, `&aspect=4:3` and
`&transition=none|fade|slide|zoom` to try themes and layouts. In the player,
deep links work: `#3` is slide 3, `#3.2` is slide 3 after two reveal steps.

## Editor

New slides are **free-form**: every block sits on the canvas at its own position, like in
Canva or Google Slides. The older fixed layouts (title, two columns, ...) still work and
can be turned into free-form slides in one click; nothing moves when you do.

**Placing things**

- Drag a block to move it. Pink guides and a gentle snap line it up with other blocks and
  the slide centre (hold Alt to switch snapping off, Shift to keep to one direction).
- Eight handles resize; the round handle rotates (Shift: 15 degree steps). Arrow keys nudge
  (Shift: further). Drag on empty canvas to select several; Ctrl/Cmd+A selects all.
- With several selected the right panel aligns, spreads and matches them. Ctrl/Cmd+G groups,
  Ctrl/Cmd+Shift+G ungroups. Lock a block to stop it moving; hide it without deleting it.
- The Layers tab lists everything on the slide: select, hide, lock, drag to reorder.
- Copy, cut and paste work between slides, decks and browser tabs. Pasting text, a link or a
  picture address makes the right block; pasting a picture makes an image block.

**Adding things**

- **Insert** (top of the canvas) searches every block type, each shown as it will look.
  Click a card, or drag it onto the slide. Text, Image, Shape, Quiz and Poll are one click.
- Press `/` and type to add a block from the keyboard. Double-click empty canvas to add text there.
- The **+** above the slide strip, or the **+** that appears between slides on hover, adds a
  slide from a template or a fixed layout.

**Making it look right**

- A small toolbar floats over the selection: size, alignment, theme colours (plus recent and
  custom ones), picture replace and crop (drag to move, scroll to zoom), duplicate, lock, layer order.
- **Arrange** (Slide tab) lays out the blocks on a slide as a title, two columns, picture left...
- **Theme** (Deck tab) shows your current slide in each theme; hover to preview on the canvas.
- Each block can have an **entrance animation** (Block tab), played when presenting.
- Zoom with the buttons above the slide or Ctrl/Cmd +, -, 0. Speaker notes sit under the slide.
- **All slides** shows the whole deck as a grid. Shift/Ctrl-click slides to select several,
  then drag, duplicate or delete them together.

`?` lists every shortcut.

| Keys | Action |
| --- | --- |
| Enter / F2 | edit the selected block |
| Esc | finish editing, then deselect |
| Ctrl/Cmd+B, I, K | bold, italic, link (while editing rich text) |
| Delete | delete the selection |
| Ctrl/Cmd+Z, Shift+Z | undo, redo (a whole typing session is one step) |
| Ctrl/Cmd+C, X, V, D | copy, cut, paste, duplicate |
| PageUp / PageDown | previous / next slide |
| Alt+Up / Down (in the slide list) | move the slide |
| Ctrl/Cmd+Enter | present (add Shift for the presenter view) |
| Ctrl+H | find and replace (also in the File menu) |
| Ctrl/Cmd+S | save now (autosave runs after every change) |

### Look and feel

- **Slide background** (Slide tab): the theme's, a colour, or a picture with a "darken" slider so text stays readable. Text switches between light and dark to suit a colour.
- **Custom colours and font** (Deck tab): pick a background and an accent; text, panels, borders and the good/bad colours are worked out from them so contrast stays at WCAG AA. A font choice sits alongside. "Back to theme colours" undoes it.
- **Logo** (Deck tab): shown on every slide in a corner you choose, in three sizes.
- **Find and replace** (Ctrl+H): matches case and whole words if you ask, optionally in speaker notes. It searches headings, text, lists, quiz questions and answers and the rest of the slide text, and leaves links, image addresses and code alone. Click a result to jump to the slide. Replace all is one undo step.

The working deck and uploaded images are stored in the browser (IndexedDB).
Use File > Export to get a portable JSON file with images embedded; Import
reads it back. Images dropped on the canvas or pasted are downscaled to WebP
when large.

## Presenting

Present from the editor (Ctrl/Cmd+Enter, or the arrow beside the button for "from
the beginning" and "with presenter view"). Keys while presenting; `?` shows them:

| Key | Action |
| --- | --- |
| Arrows, Space, Page keys, Home, End | move through slides and reveal steps |
| O or G | overview grid of every slide |
| F | fullscreen |
| P | presenter view: a second window with notes, next slide, a timer and clock |
| B or . | black screen (any key brings the slide back) |
| W | whiteboard you can draw on |
| L | laser pointer |
| D | draw on the slide (1 to 5 pick a colour, U undo, C clear); drawings stay with their slide |
| S | spotlight (scroll to resize) |
| A | pause or resume auto-play |
| Esc | turn off the current tool |

Slide settings add a countdown (shown to the speaker, optionally on screen).
Deck settings add auto-play: advance every N seconds, looping or not, for kiosks.
Remote control from a phone needs a server and arrives with the live features.

## Blocks

Content: heading, text, list, image, code, quote, divider, columns, embed.

Quiz, matching, ordering and fill-in-the-blank are "scored": the Score summary block totals all of them.

Interactive (the presenter clicks, the audience sees the result):

| Block | What it does |
| --- | --- |
| Button | next, previous, first, back, jump to any slide, or open a link, so a deck can branch |
| Quiz question | one or several correct answers, instant feedback, optional explanation |
| Score summary | the score across every scored question in the deck, with "try again" |
| Tabs, Accordion | sections that each hold other blocks |
| Image hotspots | numbered markers on a picture that open a note; drag them into place in the editor |
| Flip cards | click to turn a card over |
| Click to reveal | a question with an answer behind a button |
| Before / after | two images with a draggable divider |
| Matching | pair items by clicking or dragging; checked at the end |
| Put in order | drag or use arrows to sequence items; checked at the end |
| Timeline | step through stages with a track, dots and next/previous |
| Fill in the blank | `[answer]` blanks in a sentence, with accepted alternatives `[a\|b]` |
| Reflection prompt | a private text box that stays on the device |
| Live poll | a question the audience answers on their phones; bars fill in as votes arrive |
| Word cloud | phones send up to five words each; the most common grow biggest. One person's repeat of a word counts once |
| Open answers | free-text answers appear as cards, newest first |
| Rating scale | 1 to 5, 7 or 10 with labels at each end; shows the spread and the average |
| Ranking | each phone orders the items (arrows, so it works by keyboard); the screen sorts by points |
| Audience Q&A | phones ask and upvote; you mark questions answered or hide them. Hidden questions never reach phones |
| Chart | bar, line, pie or donut from pasted spreadsheet data, with a table for screen readers |
| Calculator | sliders feeding formulas (`people * hours * 48`), evaluated without `eval` |
| Live code | HTML, CSS and JS the audience can edit, run in an isolated frame with no network |

Design: Shape (rectangle, rounded, pill, ellipse, line, arrow), Icon (about 50 line icons that follow the theme) and Diagram (steps in a row, a column or a cycle, drawn with arrows).

Anything the audience does lives in a per-presentation session, so leaving a
slide and coming back restores it, and a score slide can read every quiz. It is
never saved with the deck.

### Adding a block type

One file that calls `registerBlock`, plus an import in `src/core/blocks/index.js`:

```js
registerBlock({
  type: 'my-block', label: 'My block', group: 'Interactive',
  defaults: () => ({ ... }),
  normalize: (props, ctx) => ({ ... }),   // clamp and validate everything
  render: (block, ctx) => element,       // pure DOM; ctx.mode is present | edit | thumb
  fields: [...],                         // what the inspector shows (segmented, toggle, text,
                                         // list, image, slide, sections, ...)
  edit: [...],                           // text you can type into directly on the slide
  mount: (el, block, ctx) => dispose?,   // behaviour for the live presentation
  mountInEdit: true,                     // also run it in the editor (visual toggles only)
  container: { key, min, max, item },    // if it holds other blocks in sections
});
```

## Deck format

```json
{
  "version": 1,
  "meta": { "title": "..." },
  "theme": { "id": "densight-dark", "overrides": {} },
  "brand": { "logo": "", "position": "bottom-right", "size": "md" },
  "aspect": "16:9",
  "transition": "fade",
  "slides": [
    {
      "id": "s_1",
      "layout": "content",
      "notes": "",
      "background": { "color": "#14213D" },
      "blocks": [
        { "id": "b_1", "type": "heading", "slot": "title", "props": { "text": "Hello", "level": 2 } },
        { "id": "b_2", "type": "list", "slot": "body", "props": { "items": ["a", "b"], "revealItems": true } }
      ]
    }
  ]
}
```

Blocks take a `slot` from their slide's layout and an optional `reveal` step
number. A block type is one file that calls `registerBlock({ type, label,
defaults, normalize, render, steps? })`.

## Live sessions

Present menu > Go live. A session has two rooms: an **audience** room (6-character
code, QR code) where phones answer polls and quiz questions and watch the totals,
and a **remote** room (long secret link) where your own phone moves the slides
and shows the speaker notes and the next slide's title. Quiz answer keys are never
sent to phones. Votes count for the slide that is showing; the presenter can click
an option too. Nothing is stored on a server: totals live in the presenter's page.

Where it runs (chosen in the dialog, saved in this browser):

| Setting | Use it for |
| --- | --- |
| Try it here | other tabs of this browser; no setup |
| Realtime server | phones. A Supabase project (its URL and public anon key; no tables or SQL needed, only Realtime broadcast), or `npm run relay` on your own network |

Phones need to open the app from an address they can reach. A deployed copy of
`dist/` works; for a local test type this computer's network address (such as
`http://192.168.1.5:5177`) under "Address phones open". The connection settings
travel inside the links and QR codes, so phones configure nothing. The anon key
is public by design; never paste a service-role key.

If the presenter's page reloads, the session resumes with the same code and links
(kept for that browser tab), and phones send their answers again so the totals
rebuild. If the presenter goes silent for 45 seconds, phones say so and recover
on their own.

Limits to know about: a room is protected only by its code (audience) or secret
(remote). Anyone who knows the code can answer, and a determined person can send
many votes under made-up ids; each prompt caps at 1000 voters. Fine for a
workshop, not for anything that must be tamper-proof. The client is
`@supabase/realtime-js`, tested here against the relay and not against a hosted
Supabase project.

## Production setup in one place

The Supabase project is compiled in at build time, so nobody types it. Set two
environment variables where the site is built (Netlify: Site configuration >
Environment variables), then redeploy:

| Variable | Value |
| --- | --- |
| `SUPABASE_URL` | the project address, `https://xxxx.supabase.co` |
| `SUPABASE_ANON_KEY` | the anon (public) key, or a publishable key |

The build stops with an error if the key is a `service_role` or secret key. For
local development put the same two lines in `.env.local` (git-ignored). Without
them the app still works and falls back to typing the project in File > Cloud.

## Accounts, online saving and share links

Sign in once and decks save online by themselves, on any device you sign in on.
The top bar shows the state ("Sign in to save online", "Saving online...", "Saved
online", "Not saved online"). Each edit is sent a few seconds after you stop
typing; a failed save says so and retries on its own. The copy in your browser
is always saved too, so nothing is lost while offline. A deck that is merely
opened (from the cloud, or New deck) is not saved until you edit it.

File > Cloud (or the top-bar button) opens the account panel: sign in, see saved
decks, open or delete them, turn a share link on or off, save a copy.

Sign-in options, all private to the account:

| Option | Notes |
| --- | --- |
| Continue with Google | appears only if you switch Google on in Supabase (Authentication > Providers > Google, with an OAuth client from Google Cloud) |
| Email me a sign-in link | works out of the box; opening the link on the same device signs you in. Supabase's built-in email sender is rate-limited, so for many users add your own SMTP |
| Password | tucked under "Use a password instead" |

Setup, once per project:

1. SQL Editor: paste and run `supabase/schema.sql`. It creates a `decks` table
   where each person can read and change only their own rows (row level
   security), and a `get_shared_deck` function that returns one deck for an exact
   unguessable token. Anonymous visitors cannot read or list the table.
2. Authentication > URL Configuration: set Site URL to your production address and
   add it (and `http://localhost:5177` if you test locally) under Redirect URLs.
   Sign-in links and Google send people back to these addresses.
3. Authentication > Providers: leave Email on. After your own account exists you
   can turn off new sign-ups (the project key is public by design).

A share link looks like `?view=TOKEN`. It opens a read-only player for anyone,
with no account. Stopping sharing deletes the token, so the old link stops
working. Images are stored inside the deck (25 MB limit in all). Two devices
editing the same deck at once is last write wins: there is no merging.

Tested against a local stand-in for the Supabase endpoints (sign-up, sign-in
links, token refresh, per-owner rows, the share function) and in a browser
against it. That does not run `schema.sql` or send real email, so before relying
on it: sign in as two accounts and confirm each sees only its own decks.

## Offline

`npm run build` writes `dist/sw.js`. Served from any http(s) address, the app
registers it and keeps its four files in a cache named after a hash of the
build, so the editor and `?play` pages load with no network. A new build gets a
new cache; the page says "A new version was installed. Reload to use it." and
the old cache is deleted. The development server removes any worker instead, so
edits are never hidden. `dist/single/index.html` needs no worker: it is one
file and opens from disk.

Decks and images are already stored in the browser, so offline editing keeps
working. Only remote images and embeds need a connection.

## Status

Phases 1 to 6 are done, with phase 6 limited to what was asked for: offline
support, shapes, icons and diagrams, a theme builder and logo, per-slide
backgrounds, and find and replace. Not built: an accessibility checker,
right-to-left languages and their fonts, a template library, Markdown import.
Phase 7: phone remote, live polls, quizzes, word clouds, open answers, ratings, rankings and Q&A, accounts, cloud decks and share links. Results can be downloaded as a CSV from the Go live dialog (built on the presenter's page; nothing is stored on a server). Not built: real-time co-editing, team workspaces, single sign-on, PowerPoint and Google Slides add-ins, importing PowerPoint, timed leaderboard quizzes, image storage outside the deck.

Known limits: Inter is bundled as the Latin subset only, so other scripts
fall back to system fonts. Code blocks are not syntax-highlighted yet.


## Plans and billing (Paddle)

Four plans: Free, Starter ($10 a month), Pro ($40) and Advanced ($120); yearly is ten months'
price, and paid plans start with a 7-day trial that needs a card. **One table**, `src/billing/plans.js`,
says what each plan includes; the pricing section, the upgrade dialog, the account page, the live room and
the database all read it (tests check they agree).

| | Free | Starter | Pro | Advanced |
| --- | --- | --- | --- | --- |
| Decks online | 3 | 25 | 100 | 1,000 |
| Phones in a live room | 25 | 100 | 500 | 1,000 |
| Question types phones can answer | poll, quiz, rating | + word cloud, open answers, ranking, Q&A | same | same |
| Your logo, colours, font | no | yes | yes | yes |
| Results as a spreadsheet | no | yes | yes | yes |
| Exports | deck file, PNG | + web page, PDF | + PowerPoint | same |
| Themes | 2 | 4 | 4 | 4 |

Building, presenting and everything on the device stay free. **What is actually enforced:** the online
deck limit is enforced by the database (a trigger in `supabase/schema.sql`; existing decks are never
deleted, only new ones refused). The rest (room size, question types, exports, branding) are locks in the
browser, because a page running on the customer's computer cannot truly stop them from editing it. They
are fair-use gates, not security.

How a purchase flows: the page opens Paddle's checkout (`src/billing/checkout.js`) with the signed-in
person's id in `custom_data`; Paddle sends a signed webhook to `/api/paddle-webhook`
(`netlify/functions/paddle-webhook.mjs`); it verifies the signature, ignores replays and old events, and
writes the `subscriptions` row through `paddle_apply()` (service role only). The page reads its own row.
Cancelling or updating a card uses the links Paddle puts in each subscription (stored on the row).

Set up, once:
1. Run the new part of `supabase/schema.sql` (it is safe to run again).
2. Create the catalog in each Paddle account and put the price ids in `src/billing/catalog.js`
   (live ids are in; fill in the sandbox ids when the sandbox catalog exists).
3. Add the variables in `.env.example` to Netlify, add a notification destination in each Paddle account
   pointing at `https://YOUR-SITE/api/paddle-webhook` (events: all `subscription.*`), and paste each
   destination's secret into `PADDLE_WEBHOOK_SECRET_LIVE` / `_SANDBOX`.
4. Build with a `test_` client token to try it with Paddle's sandbox cards; a `live_` token for real
   payments. Real payments also need a verified Paddle account and an approved checkout domain.

Known limits: switching between paid plans is done through support for now (a plan change needs
Paddle's subscription API, which needs a server key); the page asks you to write to support. Team
workspaces and single sign-on do not exist yet, so the Advanced plan sells room size and priority support only.
